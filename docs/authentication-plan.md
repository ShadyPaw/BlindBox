# Phase 2：Authentication 实施计划

目标：用户能通过邮箱和密码注册、登录，刷新后保持会话，退出使会话立即失效；密码重置只能由持有一次性邮件令牌的人完成，普通用户无法访问管理员接口。

## 实施顺序

1. 用户、会话、密码重置令牌数据模型与 PostgreSQL 迁移。
2. 邮箱规范化与输入校验、scrypt 密码哈希、随机不透明会话令牌（数据库仅存摘要）。
3. 注册、登录、当前账户、退出、忘记密码、重置密码接口；Redis 限流、来源校验、权限边界。
4. 同源前台 API 代理、真实账户表单、账户页面和重置页面；HttpOnly Cookie，不在浏览器存储中保存凭据。
5. 单元、数据库集成和浏览器全链路测试，更新环境配置、CI 和项目状态文档。

## 边界与决定

- 首版邮箱＋密码，不实现短信或 Google OAuth。用户邮箱在本阶段不自动标记为已验证，后续涉及资产的功能必须另行落实邮箱验证要求。
- 新账户固定为 USER；客户端不能指定角色。管理员角色通过受控运维变更赋予，无公开提权接口。
- 会话固定有效期，退出删除当前会话；密码重置使该用户全部旧会话失效。并发登录与重置通过用户行锁串行化，避免旧密码验证后创建新会话。
- 密码最少 15、最多 128 个字符，不裁剪、不限定字符组合；使用 Node.js scrypt，独立随机盐和恒定时间比较。
- 重置令牌 30 分钟有效、只能消费一次；重置不自动登录。请求重置使用统一响应，避免泄露账户是否存在。
- 本地邮件写入被 Git 忽略的 `.local/mail`；生产使用 SMTP，缺少配置时邮件功能明确不可用，不伪报已发送。
- Web 代理只转发固定认证路径和必要标头；浏览器写请求须携带同源 Origin 和自定义标头。API 再次校验来源，不依赖 CORS 作为访问控制。
- 本阶段不实现钱包、开箱、背包、支付或完整后台业务界面。

## 验收

2026-09-18：上述五项实施工作已完成；22 项单元测试、8 项集成测试、9 项浏览器测试通过。生产 SMTP 和 Docker 运行验收尚未在本机完成。

- 正确登录／错误密码、重复注册、非法输入、越权角色输入、限流和 CSRF 拒绝。
- 注册后会话可读取，退出后旧 Cookie 失效；过期会话被拒绝。
- 重置令牌不出现在 API 响应或日志中；过期／重放被拒绝；并发消费只有一次成功；旧会话全部失效。
- 前台完成注册、刷新、账户页、退出、密码重置和重新登录。
- 完整 lint、类型检查、测试、构建通过；生产邮件实际投递仍需要部署方配置 SMTP 后验收。
