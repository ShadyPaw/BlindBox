# 钱包与充值 UI 原型

2026-09-19：新增 `/wallet`，沿用现有深色／紫色主题。桌面导航、手机导航和账户页均提供入口。页面为公开原型，全部数据明确标注为虚构，与登录用户无关。

本轮参考站浏览器连接超时，未取得登录后的钱包界面。因此本版完成的是现有风格下的交互原型，不能宣称原站钱包已完成 1:1 验收；取得原站页面后仍需逐项核对布局、渠道、字段和交互。

## 已实现

- USD／COIN 切换、可用与冻结余额、收入／支出筛选、流水详情。
- 金额预设与自定义、即时清除旧错误、提交时明确提示范围与精度。
- 选择支付方式、上一步保留输入、确认金额、处理中及成功／失败／取消演示。
- 关闭、Escape、遮罩关闭；再次打开从初始步骤开始，关闭时取消未完成请求。
- 零余额、空列表、服务不可用、重试和加载状态；页面底部“预览情境”可切换。
- 桌面与手机布局；支付成功演示不增加余额、不追加流水、不发起支付请求、不保存付款资料。

本版示例充值范围为 USD 5–1,000，不是已确定的业务限额。所有金额使用整数 minor units 字符串，经 `@box/money` 转换和展示；不以浮点计算金额。COIN 不提供充值或兑换。

## 数据层与接口草案

组件只通过 `WalletGateway` 获取示例余额／流水、创建及查询演示订单。类型在 `packages/types` 中；`createWalletPreview` 是显式的内存演示实现，不是生产服务的降级方案。刷新或关闭演示丢弃订单；不写入 PostgreSQL、localStorage 或真实账户。

以下 HTTP 路径仅供后续对接讨论，本轮 **没有实现**：

| 拟议接口                      | 用途                                       |
| ----------------------------- | ------------------------------------------ |
| `GET /wallet/balances`        | 查询当前登录用户各币种余额                 |
| `GET /wallet/transactions`    | 查询当前用户流水；后续补充服务端筛选与分页 |
| `POST /payments/recharges`    | 创建充值订单；服务端校验金额、渠道和幂等键 |
| `GET /payments/recharges/:id` | 查询属于当前用户的支付订单                 |

余额草案使用 `unit / availableMinor / frozenMinor`。流水金额为非负整数字符串，另用 CREDIT／DEBIT 表达方向。充值草案使用 `amountMinor / unit / methodId`；订单状态为 PENDING／SUCCEEDED／FAILED／CANCELLED。

真实接入时必须补充服务端身份与归属校验、请求及响应验证、同源代理、CSRF、幂等、分页、渠道限额与费用、支付行动信息和错误契约。演示特有的“结果选择器”必须移除；它不属于真实请求参数。渠道未确定前不固定 redirect／二维码／嵌入支付的结构。

支付成功必须由后端验签并确认到账后入账，前端查询最终状态。浏览器跳转或点击“已付款”不能改变余额。服务故障必须明确展示，不能回退到演示数据。真实钱包页届时改为服务器端认证保护。

## 阶段边界

Phase 4 钱包账本、Phase 8 支付仍未实现。没有钱包数据库模型、真实记账、支付渠道、提现、兑换、转账、真实订单或管理员写接口。认证和 Catalog 行为保持不变。

## 验证

新增单元测试覆盖整数金额边界、演示成功不入账、实例隔离、请求取消与故障不返回伪造余额。浏览器测试覆盖币种／筛选／详情、空态与故障、金额精度、上一步保留输入、成功／失败／取消、手机布局、关闭重开，以及演示期间没有 POST 请求。
